# Workflow: Plan to PR

Move an approved plan into a reviewable pull request.

## Required PR Contents

- linked task ID
- problem
- goal
- summary of changes
- affected files and packages
- validation commands and results
- screenshots or Storybook references for UI changes
- public API impact
- migration notes, if needed
- risk assessment
- follow-up tasks

## Rules

- The PR must match the task scope.
- Handoff and verification must be complete before requesting review.
