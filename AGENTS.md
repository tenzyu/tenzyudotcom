# Repository agent contract

- Read the nearest `package.json`, its public `exports`, `project.json`, and tests. Use the [workspace architecture reference](docs/wiki/architecture.md) to find component owners. Source code and observed behavior override documentation.
- Products compose libraries. Generic UI components must not depend on supporting UI components. Neither may depend on product code. The publishing and skin domain libraries define business invariants. The revisioned-content library implements persistence, not product rules. `repo-ops` is never a runtime dependency. Add reusable capability through the owning public API, not another application wrapper.
- Use the existing Bun workspace and Nx tasks: `bun nx show project <name> --json`, `bun nx run <name>:check`, `bun nx run <name>:verify`. On neko7, use its existing direnv shell. Elsewhere, enter the appropriate Nix devShell once. Preserve existing routes, data, authorization, publication consistency and native filesystem safety.
- Base topic branches on `develop`. Without scoped authorization, do not merge, deploy, write external content, or push to `main`. Never read or expose secrets or `.env*`. Keep private evidence outside Git. Report failed and unrun checks. State which changes can be rolled back.
- Historical ADRs are records, not instructions. Update the relevant architecture or operations entry only for durable changes supported by code. Never invent verification.
