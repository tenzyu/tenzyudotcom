## Repository instruction for LLM agents

Do not rely on prior chat context. The active objective is the Atelier Autopoiesis goal in:

```txt
harness/atelier-autopoiesis/GOAL-ATELIER-AUTOPOIESIS.md
harness/atelier-autopoiesis/MISSION.md
harness/atelier-autopoiesis/EVALUATION-SPEC.md
harness/atelier-autopoiesis/AUTONOMY-CONTRACT.md
harness/atelier-autopoiesis/TOKEN-ECONOMY-CONTRACT.md
harness/atelier-autopoiesis/AGENT-INPUT-MATRIX.md
```

The purpose is not to produce an analysis, plan, MVP, or hand-written checklist. The purpose is to cause the repository implementation to converge toward the mission: a repository-side semantic control plane that makes specifications, decisions, validation, authority, history, stale state, and agent permissions machine-operable.

## Primary goal command

```txt
/goal @atelier-autopoiesis-coordinator Execute @harness/atelier-autopoiesis/GOAL-ATELIER-AUTOPOIESIS.md against the current repository. Do not stop at analysis. Continue by dispatching implementation and evaluator agents until the evaluator returns pass or a true product-author decision is blocked.
```

## Non-negotiable boundaries

- `harness/atelier-autopoiesis/**` is the control pack for this run. Treat `GOAL-ATELIER-AUTOPOIESIS.md`, `MISSION.md`, `EVALUATION-SPEC.md`, and `AUTONOMY-CONTRACT.md` as input authority. Do not edit canonical files. Generated run artifacts may be written only under `harness/atelier-autopoiesis/work/**`.
- Existing `harness/atelier-design-docs/**` is historical/design input. Use it as context, not as the ceiling of the product.
- `.atelier-bootstrap/**` is implementation tooling in the attached snapshot and may be edited by implementers when the work order allows it.
- `.atelier/v0/**` is generated runtime state and views. It may be regenerated by commands; do not hand-edit it as a substitute for runtime behavior.
- Generated views are never truth.
- Handoffs are transport artifacts, not authority.
- LLM-derived records must never become `accepted` or `verified` without promotion/evidence checks.
- If an agent can pass by weakening validators, deleting evidence, narrowing the mission, treating a prototype as complete, or asking the user for implementation sequencing, the agent is failing the goal.

## Completion discipline

Only `atelier-autopoiesis-coordinator` may emit final-line markers:

```txt
[goal:complete]
[goal:blocked]
```

`[goal:complete]` is valid only after `atelier-autopoiesis-evaluator` returns `status: "pass"` with command/static evidence. If work remains and no product-author decision is needed, continue the loop instead of asking the user what to do.

Do not claim Bun, Nx, or tests passed unless the command actually ran.

## Token and context discipline

The total completion budget is 100M tokens across input, cached input pressure, reasoning, and output. MiniMax M3 reasoning effort is prompt-controlled only. Agents must follow `TOKEN-ECONOMY-CONTRACT.md`, `SUBAGENT-EXECUTION-CONTRACT.md`, and role-specific execution contracts.

Do not broad-read generated state, archives, or logs. Use inventory, slices, summaries, and runtime queries. Before phase finalization or goal completion, produce a three-scenario token forecast using `TOKEN-FORECAST-SPEC.md`.
