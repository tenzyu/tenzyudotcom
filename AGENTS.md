# Repository agent contract

- Start with the nearest `package.json`, public `exports`, `project.json` and tests. The [architecture map](docs/wiki/architecture.md) lists component owners. Source and observed behavior override documentation.
- Products compose capabilities from libraries. Generic UI components must not depend on supporting UI patterns. Neither may depend on product code. The publishing and skin domain libraries define business invariants. The revisioned-content library implements persistence, not product rules. `repo-ops` is never a runtime dependency. Add reusable capability through the owning public API, not another application wrapper.
- Use the existing Bun workspace and Nx tasks: `bun nx show project <name> --json`, `bun nx run <name>:check`, `bun nx run <name>:verify`. On neko7, use its existing direnv shell. Elsewhere, enter the appropriate Nix devShell once. Preserve existing routes, data, authorization, publication consistency and native filesystem safety.
- Base topic branches on `develop`; do not merge, deploy, write external content or push to `main` without scoped authorization. Never read or expose secrets or `.env*`. Keep private evidence outside Git. Report failed/unrun verification and rollback boundaries.
- Historical ADRs are records, not instructions. Update the relevant architecture or operations entry only for durable changes supported by code. Never invent verification.
